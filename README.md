# Threat Information Exchange Service — Go Backend

Реализовал REST API для хранения, получения и обновления информации об угрозах на основе OpenAPI 3.0.

**Стек:** Go, net/http, PostgreSQL, pgx/pgxpool, Docker Compose, SQL-миграции.

Разработал многослойную архитектуру Handler → Service → Repository. Добавил валидацию входных данных, обработку ошибок PostgreSQL и HTTP-ответов. Настроил ограничения целостности данных, контексты, таймауты, логирование через slog и graceful shutdown. Конфигурация загружается из переменных окружения с поддержкой `.env`.

Расширил модель угрозы описанием, типом, уровнем опасности и временем создания и обновления. Добавил юнит-тесты и интеграционный тест с настоящим PostgreSQL и HTTP-сервером.

## API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| POST | `/info` | Создать угрозу с уникальным MD5 |
| GET | `/info/{md5}` | Получить информацию об угрозе |
| PUT | `/info/{md5}` | Заменить информацию о существующей угрозе |

Контракт и примеры запросов: [openapi.yaml](openapi.yaml).

## Запуск

Нужен Docker с Compose. Если `.env` ещё нет, создайте его по примеру `.env.example` и задайте свой `POSTGRES_PASSWORD`. Compose подставляет этот пароль в настройки API и PostgreSQL; в `compose.yaml` хранится только ссылка на переменную. Для локального примера используйте пароль из букв, цифр, дефисов и подчёркиваний, чтобы его можно было использовать в URL. Из контейнера API база доступна по имени `db`.

Рабочий `.env` исключён из Git и контекста Docker-сборки. В репозиторий добавляется только `.env.example` с заглушками. Для уже созданной базы используйте её существующий пароль.

```sh
docker compose up --build -d
```

API: `http://localhost:8080`. PostgreSQL: `localhost:5433`, пользователь `app_user`, база `threats`.

Up-миграции применяются при первом создании базы. Данные сохраняются в Docker-томе; изменение имени пользователя или пароля в Compose не меняет учётные данные уже созданной БД.

Остановка:

```sh
docker compose down
```

## Тесты

Нужен Go 1.25 или новее. Запуск юнит-тестов:

```sh
go test ./...
```

Без `TEST_DATABASE_URL` интеграционный тест пропускается. Для запуска с БД из Compose в PowerShell:

```powershell
$env:TEST_DATABASE_URL = 'postgres://app_user:YOUR_PASSWORD@localhost:5433/threats?sslmode=disable'
go test ./integration -v -count=1
```

Замените `YOUR_PASSWORD` паролем своей БД. Тест проверяет создание, чтение, обновление, дубликат MD5, необязательную severity и ответы 404. Он применяет миграции в отдельной схеме и удаляет её после завершения. Существующие таблицы не очищаются; роли БД нужно право CREATE на базу.
